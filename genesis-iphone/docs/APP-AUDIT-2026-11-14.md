# Genesis app audit — November 14, 2026

Scope: the iPhone/iPad Genesis Controller app and Mac companion for Mini 1 and Mini 2. This audit does not change Genesis Mini firmware. Mobile build: **0.1.0 (13)**.

## Repairs

- Preserve recognized words when Speech emits an empty result, finishes after a pause, or renews a recognition task. Renew long requests at 45 seconds and quiet requests after four seconds without changed text; buffer incoming audio across renewal.
- Preserve final words on release, reject stale callbacks after cancellation, and prevent a duplicate release or old authorization callback from interrupting a newer recording.
- Make mapped Hold to talk actions toggle local recording instead of requesting a panel that did not exist. The wide microphone key remains hold/release. Neither action sends a message.
- Keep local Stop available during a recording even if the Mac connection drops. Restore draft review readiness after an interruption.
- Prevent draft edits during capture/finalization from being overwritten by later recognition output.
- Stop recording on gesture cancellation/drag-out and backgrounding. An ordinary inactive transition, including a permission alert, no longer cancels toggle-based authorization by itself.
- Explain unavailable quick keys while preserving long-press remapping and existing assignments.
- Keep mapping and artifact search visible on iPad. Add an accessible artifact refresh label, explicit QR Cancel, and camera/invalid artifact error feedback.
- Correct stale descriptions that incorrectly said Codex phone Send was unavailable. Preserve the Change model action from the preceding update.

## Real limitations

- **Muse remains unconnected.** Registered artifact browsing is separate from Muse chat controls.
- **Two-way native Voice mode is not implemented.** Hold to Talk is speech-to-text draft capture, followed by explicit Send.
- **Steer is not wired into Genesis.** The installed Codex app-server exposes a turn-specific steer API, but it requires a separate implementation with active-turn validation and duplicate-send protection. The existing queue route must not be presented as Steer.
- **Codex Queued confirms acceptance, not delivery.** Claude delivery can remain uncertain when its UI cannot prove completion. Uncertain messages are not resent automatically.
- **Change model controls the current Codex Mac view.** Its default Control–Shift–M binding must remain available. Reselect a chat if menu navigation clears the mobile route.
- **Artifacts must be registered** with the companion; automatic discovery is not implemented. Photos-library thumbnail navigation still requires the Mac mouse; regular folder navigation is separate.
- No live agent message, permission approval, destructive shortcut, or real microphone session was executed during this audit. The automated evidence does not certify every third-party desktop control or recognition accuracy.

## Build 14 follow-up: recording again after release

The user reported that the first recording worked, but releasing, waiting five seconds, then holding again entered RELEASE TO REVIEW without recognizing more speech. This is a failed real-device follow-up, so build 13's microphone behavior is not considered fully verified.

Build 14 creates and disposes a fresh input engine/tap for each separate hold, preserving the existing draft and the recognition-renewal flow within a hold. It rejects stale/empty buffers and reports a saved-draft error if no audio arrives within three seconds. The precise cause of the observed device failure is still unconfirmed; real speech after the second hold must be checked again.

Validation: 112 input lifecycle checks, 126 transcript checks, 157 HTTP/store checks, and the three-hold/five-second-gap UI scenario on both simulators passed. The signed iPhone/iPad build passed and build14 was installed and launched on both physical devices. These tests use synthetic buffers or demo input, not a real microphone.

Diagnostics stay on the device in `Library/Caches/GenesisDiagnostics/dictation.jsonl`: at most 128 events containing fixed lifecycle names and numeric counts. They contain no speech, audio, chat identifiers, endpoint addresses, or credentials. Read the file before relaunching after a failure, since the in-memory event ring starts anew per process.

Build14 acceptance: the user repeated the two-sentence test on the iPhone with Mini2 → Claude, releasing between holds and waiting five seconds. They confirmed: “Yes, both sentences appear.” This confirms the reported second-hold failure is resolved in that tested flow. It does not extend the result to every audio route or longer uninterrupted recording.

## Build 15 follow-up: Codex draft losing words

The user subsequently reported that Codex dictation was cutting off text, then clarified: “Earlier words disappear while I’m talking.” Build14's earlier two-hold confirmation does not establish that this separate failure is resolved.

Content-free iPhone diagnostics showed audio buffers, recognition results and a prompt final result after release for the inspected captures. There was no input-watchdog failure, recognition error, renewal or finalization timeout in those captures. These events do not contain the words spoken and cannot identify the exact result that lost text.

Three data-loss cases were reproduced in the shared transcript accumulator before repair: a nonempty shorter prefix/suffix replaced an existing sentence; a new utterance with missing/reset timestamps replaced earlier speech; and a wide-timestamp final containing only the last phrase removed committed earlier phrases. The repair preserves earlier fragments, merges overlapping continuations, and requires ordered textual coverage before replacing accumulated task fragments. Ordinary same-phrase corrections remain supported. Ambiguous timestamp-free recognition can still be imperfect; automated cases are not proof of every real recognition result.

Removed the four-second renewal triggered by unchanged recognition text: lack of a changed transcript is not evidence of acoustic silence. The existing 45-second renewal remains. Diagnostics now include deduplicated numeric incoming/before/after text lengths and finalization-timeout events, without recording transcript content.

Independent review also reproduced a corrected cumulative final duplicating earlier sentences. A bounded same-audio word correction now handles that case without allowing shortened finals to remove earlier phrases.

Validation: 144 transcript checks and 172 HTTP/store checks passed. The latter route real accumulator output through both Codex and Claude draft handling, verify release and persistence, and do not send messages. The signed iPhone/iPad Release build passed with version 0.1.0 (15), and its signature was verified. Build15 was installed in place and launched on the user's iPhone 17 Pro and iPad A16; device readback confirms version 15 on each. Mac companion and physical controller firmware are unchanged.

Build15 acceptance: the user tested Genesis on the iPhone with Mini2 → Codex, holding Talk through several sentences and a pause, then releasing without sending. Asked whether the earlier sentences stayed during continued speech and after release, they confirmed: “Yes, all the sentences stay.” This confirms the disappearing-words repair in that real-device flow. The iPad and Claude use the same repaired accumulator, but this follow-up does not independently confirm their live microphone behavior.
